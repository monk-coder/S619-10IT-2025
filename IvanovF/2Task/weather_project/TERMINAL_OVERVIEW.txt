=============================
TERMINAL ARCHITECTURE OVERVIEW
=============================

1. Общая идея
--------------
Веб-терминал состоит из фронтенд-модулей на JavaScript. Они отвечают за хранение состояния, регистрацию команд, работу интерфейса и выполнение сетевых запросов. Основные части лежат в каталоге `weather/static/weather/js/`.

2. Структура ключевых файлов
-----------------------------
• terminal-state.js — единое хранилище состояния терминала. Здесь описаны
  все сохранённые данные (заметки, задачи, параметры казино, сведения о
  пользователе, таймеры и т. д.), а также функции для чтения/записи из
  localStorage и обновления UI (история запросов, часы, вывод текста).

• terminal-services.js — «тонкий» слой сервисов, который общается с backend
  через fetch (история, задачи, авторизация, время). Каждый метод аккуратно
  обновляет state и игнорирует сетевые ошибки там, где это безопасно.

• terminal-commands.js — центральный реестр команд. Хранит список команд,
  алиасы, подсказки, перехватчики ввода и утилиты (например, генератор ASCII
  таблиц). Именно здесь находится функция executeCommand, которая разбирает
  введённую строку, даёт шанс перехватчикам (казино) и запускает нужную
  команду.

• terminal-main.js — точка входа. После загрузки страницы вызывает init,
  навешивает обработчики на поле ввода, синхронизирует подсказки/курсоры,
  выводит приветственное сообщение и запускает периодическое обновление
  времени.

• commands/*.js — отдельные файлы с командами (weather, tasks, casino и
  т. д.). Каждая команда само-регистрируется через TerminalApp.registerCommand
  и описывает собственную бизнес-логику. В командном каталоге есть как
  простые локальные команды (clear, notes), так и те, что делают запросы к
  серверу (weather, flight, currency). Файл casino.js использует перехватчики
  для многошагового ввода.

3. Поток работы команды
-----------------------
1) Пользователь вводит строку → terminal-main.js отображает её и вызывает
   TerminalApp.executeCommand.
2) terminal-commands.js создаёт контекст, запускает перехватчики (казино) и
   затем выполняет зарегистрированную команду.
3) Команда при необходимости обращается к terminal-services.js (fetchHistory,
   fetchTasks и т. д.) или к state-функциям (например, TerminalApp.addNote).
4) Вывод результата производится через TerminalApp.print/printHtml, а UI
   автоматически прокручивается до конца и обновляет часы/подсказки.

4. Состояние и сохранение
-------------------------
• Заметки и настройки казино хранятся в localStorage. При старте терминал
  вызывает restoreState, чтобы восстановить данные.
• История запросов и задачи приходят с бэкенда при syncAuthStatus, но только
  если пользователь авторизован.
• Текущее состояние казино (баланс, ставка, выбранный режим) доступно через
  get/set-функции TerminalApp и синхронизируется с localStorage после каждого
  изменения.

5. Перехватчики ввода
---------------------
• casino.js добавляет собственный перехватчик через registerInterceptor.
  Он анализирует каждую введённую строку, пока игрок находится внутри
  игрового цикла (возраст, меню, ставки), и блокирует стандартное выполнение
  команд до завершения игры.

6. Автодополнение
-----------------
• terminal-commands.js хранит массив названий команд и умеет вычислять
  подсказку, когда курсор стоит в конце строки. Подсказка подсвечивается в
  полупрозрачном span («ghost-hidden»), а по Tab значение автоматически
  дописывается в input.

7. UI и обновление времени
--------------------------
• terminal-state.js содержит функции updateCursorPosition, updatePrompt и
  updateClockDisplay. Их вызывают terminal-main.js и terminal-services.js,
  чтобы синхронизировать визуальное состояние (курсор, приглашение, часы).

В результате эти модули совместно обеспечивают работу терминала: пользователь
видит знакомое текстовое окружение, вводит команды, получает ответы, а система
хранит настройки и историю между сессиями.
